RAILRESERVE PROJECT PROGRESS REPORT
==================================
Report date: 21 October 2026

PROJECT OVERVIEW
----------------
RailReserve is a native Android application built with Java, XML layouts,
and SQLite. Live station and scheduled train search uses the Node.js backend
as an adapter to the RailRadar provider. The app also contains a local demo
booking workflow.

Demo bookings are stored locally on the device. They are not IRCTC
reservations, do not issue real railway tickets, and do not process payments.
Live data is scheduled timetable information; live running status, fares,
live seat availability, and real booking are not enabled.

BUILDING THE DEBUG APK
----------------------
From PowerShell at the project root:

    .\gradlew.bat :app:assembleDebug

The debug APK output is:

    app\build\outputs\apk\debug\app-debug.apk

The default debug backend address is http://10.0.2.2:3000, for an Android
emulator talking to a backend on the development computer.

For a physical phone, first get the computer's current Wi-Fi IPv4 address
(for example, with ipconfig), then build using that address:

    .\gradlew.bat :app:assembleDebug -PrailreserveDebugBackendUrl=http://192.168.1.20:3000

Replace 192.168.1.20 with the actual address. Install the newly built APK;
an existing installed APK keeps the address it was built with. Keep the
backend running, and make sure Windows Firewall allows inbound TCP port 3000.
The phone and computer must be able to communicate over the Wi-Fi network.

To install with ADB:

    adb install -r .\app\build\outputs\apk\debug\app-debug.apk

See README.md for complete backend setup, release build, and troubleshooting
instructions.

BACKEND SETUP SUMMARY
---------------------
From PowerShell:

    Set-Location .\backend
    Copy-Item .env.example .env

Set RAILRADAR_API_KEY in backend\.env using a text editor. Keep the key
private; do not add it to the Android app or source control. Then run:

    npm install
    npm start

Check backend process health:

    curl.exe --noproxy "*" http://127.0.0.1:3000/health

Check live station lookup:

    curl.exe --noproxy "*" "http://127.0.0.1:3000/api/stations/search?q=Delhi"

REMAINING NOTES
---------------
- The backend must be running for live station/train searches.
- The phone build's configured laptop address can become stale if the
  computer reconnects to Wi-Fi and receives a different address. Rebuild with
  the new address when that happens.
- If the phone cannot open the backend health URL, check the current laptop
  Wi-Fi IPv4 address, Windows Firewall inbound access to TCP port 3000, and
  whether the Wi-Fi network isolates wireless clients.
- README.md and gradle/wrapper/gradle-wrapper.properties have uncommitted
  documentation/configuration edits, as do the Tickets-section source,
  layout, and strings changes. These latest changes have not been committed
  or pushed.
- backend\.env and generated build outputs are local/private or generated
  files and should not be committed.
